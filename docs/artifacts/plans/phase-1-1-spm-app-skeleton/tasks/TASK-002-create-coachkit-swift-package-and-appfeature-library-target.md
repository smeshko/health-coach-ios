# TASK-002: Create CoachKit Swift package and AppFeature library target

Depends on: TASK-001
Suggested commit: `feat(foundation): add CoachKit package and placeholder AppFeature`

## Goal

Create the root `Package.swift` (`CoachKit`) and an `AppFeature` library target with a placeholder TCA
reducer + view, so `swift build` succeeds cleanly under the Swift 6 language mode.

## Files

- `Package.swift` (new) — `swift-tools-version: 6.3`; package `CoachKit`; platforms
  `[.iOS(.v26), .macOS(.v14)]` (the `.macOS` line is required so `swift build`/`swift test` compile on
  the host — see the manifest comment and round-2 #12); dependency on `swift-composable-architecture`;
  one library product `AppFeature` → target `AppFeature`.
- `Sources/AppFeature/AppFeature.swift` (new) — `public @Reducer struct AppFeature` with
  `@ObservableState public struct State: Equatable`, a minimal `public enum Action` (single
  `onAppear` case), `public init()`, and a `body` returning the placeholder reducer.
- `Sources/AppFeature/AppView.swift` (new) — `public struct AppView: View` taking
  `StoreOf<AppFeature>`, rendering the placeholder.
- `Package.resolved` (new, generated by resolution) — committed.

## Acceptance

- [ ] `swift build` completes successfully **with no warnings** under the Swift 6 language mode.
- [ ] The `AppFeature` library product is declared and exports `public` `AppFeature` and `AppView`.
- [ ] No test target, no `CoachCore`, and no dependency beyond TCA are introduced (those are 1.2 / later).

## Steps

### RED
- [ ] Verification gate for this phase is a **clean `swift build`** (the TestStore/snapshot harness is
      Phase 1.2, so there are no unit tests yet). Before any source exists, `swift build` fails — that
      is the starting "red".
- [ ] Confirm toolchain readiness: `xcodebuild -version` (Xcode 26), `swift --version` (6.3).

### GREEN
- [ ] Write `Package.swift`:
  ```swift
  // swift-tools-version: 6.3
  import PackageDescription

  let package = Package(
    name: "CoachKit",
    // .iOS(.v26) is the product baseline. .macOS is REQUIRED so the package compiles for the macOS
    // host under `swift build` / `swift test` — TCA's products require macOS 13+, so an iOS-only
    // platforms line makes the host build fail to compile (validation round-2 #12, verified). The
    // .macOS line governs only host build/test; the shipped app target stays iOS-only (xcodeproj).
    platforms: [.iOS(.v26), .macOS(.v14)],
    products: [
      .library(name: "AppFeature", targets: ["AppFeature"]),
    ],
    dependencies: [
      .package(url: "https://github.com/pointfreeco/swift-composable-architecture", from: "1.17.0"),
    ],
    targets: [
      .target(
        name: "AppFeature",
        dependencies: [
          .product(name: "ComposableArchitecture", package: "swift-composable-architecture"),
        ],
        swiftSettings: [
          // Explicit Swift 6 language mode = complete strict concurrency. Already the default from
          // `swift-tools-version: 6.3`; stated here to self-document and to satisfy the epic's
          // "strict-concurrency build settings" wording. NOT the Swift-5-mode
          // `-strict-concurrency=complete` flag / `StrictConcurrency` upcoming-feature.
          .swiftLanguageMode(.v6),
        ]
      ),
    ]
  )
  ```
- [ ] Write `Sources/AppFeature/AppFeature.swift`:
  ```swift
  import ComposableArchitecture

  @Reducer
  public struct AppFeature {
    @ObservableState
    public struct State: Equatable {
      public init() {}
    }

    public enum Action {
      case onAppear
    }

    public init() {}

    public var body: some ReducerOf<Self> {
      Reduce { _, action in
        switch action {
        case .onAppear:
          return .none
        }
      }
    }
  }
  ```
- [ ] Write `Sources/AppFeature/AppView.swift`:
  ```swift
  import ComposableArchitecture
  import SwiftUI

  public struct AppView: View {
    let store: StoreOf<AppFeature>

    public init(store: StoreOf<AppFeature>) {
      self.store = store
    }

    public var body: some View {
      VStack(spacing: 12) {
        Image(systemName: "figure.run")
          .font(.largeTitle)
        Text("Coach")
          .font(.headline)
      }
      .onAppear { store.send(.onAppear) }
    }
  }
  ```
- [ ] Run `swift build`; resolve the TCA version and commit the generated `Package.resolved`.

### REFACTOR
- [ ] Confirm **zero** warnings (treat any concurrency or unused-binding warning as a failure).
- [ ] Keep only the explicit `.swiftLanguageMode(.v6)` setting; do **not** add the Swift-5-mode
      `-strict-concurrency=complete` flag or the `StrictConcurrency` upcoming-feature — under Swift 6
      mode those are redundant (see `RESEARCH.md`).
- [ ] Note the build scope: `swift build` compiles for the **macOS host** under Swift 6 mode, so the
      "no warnings" guarantee here is validated on the host toolchain. The **iOS-target** build (and its
      own no-warnings check) happens via the xcodeproj build in TASK-003.

## Notes

- `from: "1.17.0"` is a floor; let SPM resolve the latest stable 1.x and pin it via `Package.resolved`.
- Everything the app target will import must be `public` (the `@Reducer`/`@ObservableState` macros
  generate the conformances; the `struct`, `init`s, `State`, and `AppView` must be `public`).
- The single `onAppear` action keeps the `Action` enum non-empty and models the real send pattern;
  it is a placeholder, not product behaviour.
